# Pinned ESP32-S3 WAPI behavior specification

This bundle describes the ESP-IDF 6.0.3 `libwapi.a` using independently written behavioral prose and non-executable ABI data. It contains no decompiled implementation, original instructions, or implementation recipes tied to machine registers. The specification author may inspect original artifacts; the implementation author must not. `provenance.json` pins the original objects. Public SDK declarations live separately under `public-sdk`, with original license notices.

Status: FULL BEHAVIORAL CONTRACT for all42 inventoried bodies; observed normal-path exchange vectors included. See04 for execution evidence and explicit limits. `body-scope.json` inventories all 42 original bodies: 21 public functions and 21 private helpers. `export-data.json` lists four exported data objects. This is a compatibility target, not evidence of complete protocol correctness or a security-reviewed WAPI implementation.

Target ABI is little-endian Xtensa windowed, 32-bit pointers, 32-bit int/size_t, 16-bit short. Unless stated otherwise return integers are signed 32-bit. `sm` below means an opaque mutable 428-byte context. Owned pointers inside it use the pinned OS allocator, not arbitrary caller allocation. The context ABI is observed behavior, not a published C type. No function is weak. Ordinary caller preconditions apply: buffers must cover the specified sizes; pointer arguments are not generally validated. Cases involving invalid pointers or original uninitialized memory must not be assigned invented deterministic semantics.

The original revision data symbol is a **writable 32-bit pointer to the NUL-terminated string `da143fa`**, not an all-zero integer; raw zero bytes in export-data are a relocation placeholder. Preserve the pointer type and spelling. SM4 tables Sbox (256 byte entries), CK (32 uint32_t entries), FK (4 uint32_t entries) are read-only exported standard SM4 constants. Their listed hex is target little-endian data, not code.
