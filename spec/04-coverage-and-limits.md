# Specification closure and validation boundaries

The prose covers all42 bodies in body-scope.json. Private helpers are functional decompositions, not required external exports: SM4 block/key schedule and shared WPI transform are in01; selector writer and selector mapping in02; notify/BSSID/IE bridges, key installation, Ethernet send, base-key derivation and lifecycle in02; ADDID/MIC/key-ID/fragment checks, request generation, dispatch and receive in03. Public function/data ABI is enumerated in01 and export-data.json. Independent reimplementation may organize those behaviors differently while preserving external exports and registered callbacks.

The selector-writing helper writes exactly00:14:72:last-byte(value), advances caller's byte pointer by4; its historical put_be32 name does not mean arbitrary32-bit serialization. No hidden function bodies remain outside the42 inventory.

An original-only composed oracle exercised40 bodies and2244/2619 unique instructions. Its only unexecuted bodies are public WPI decrypt and MIC, which have separate composed crypto coverage. These counts describe execution evidence, not exhaustive path validation. The original-only runner, memory snapshots and raw observation records are kept outside this implementer-facing bundle. Runner SHA256: 48811329491b01e7bbfe8f2fc5467944ed434fc73b4145c2d316ac07ba9e8cd0. No instruction bytes/traces appear in the public JSON vectors.

handshake-vectors.json supplies a complete deterministic unicast/multicast exchange and context/driver effects from that original-only oracle, with standard Python HMAC-SHA256 at the SDK boundary. ie-vectors.json captures permissive IE boundary cases. Pointers are normalized because allocation addresses are not ABI values. The driver receive/state/packet bodies execute directly; no private WAPI helper is replaced with an expected-answer stub.

Known limits and undefined cases: allocator failure on initial fragment has no safe original path; NULL global receive dereferencesNULL at final cleanup; missing HMAC callback in expansion can expose uninitialized temporary bytes; oversized/aliased caller buffers and malformed huge lengths are not memory-safe. Repeated init leaks old state. These are compatibility observations, not requirements to introduce exploitable behavior. A defensive reimplementation can reject such out-of-contract calls if it explicitly records the divergence. Do not silently report exact equivalence for them. No real WAPI AP association has yet been observed; no certificate-authentication implementation is present. Timing, interrupt interleavings, exact log message text and undefined stack contents are not established equivalence targets. Callback order, mutation order and ordinary failures are specified.
